# Paper Experiment / Code Audit

This audit maps the experiments reported in the final paper to runnable code
in this repository. It does not depend on the removable `paper/` source
directory. TensorRT-only throughput, batching, memory, and decode-breakdown
experiments are intentionally out of scope.

## InfLLM-V2 recovery

The previously missing compatibility experiment was recovered from an
untracked directory in the original experiment worktree. The two
score-producing Python files were preserved byte-for-byte. A portable
launcher, summary script, documentation, and CPU tests were added around them
in the public repository.

The recovered code loads `openbmb/InfLLM-V2-Long-Sparse-Base`, disables its
native sparse-attention path, and applies the paper's real-query, exact-Wq,
and rank-256 EarlySelect routing variants through a PyTorch attention patch.
Stage 2 is evaluated with dense attention logits plus the selected sparse
block mask. It is therefore an accuracy/compatibility experiment, not a CUDA
throughput reproduction. See `analysis/es_infllmv2/README.md` for the exact
scope and commands. The paper's "native routing" label refers to the
target-layer real-query control; it is not presented as a CUDA-kernel timing
measurement.

The host-local 260 MB low-rank cache, generated predictions, summaries, and
machine-specific launchers were not copied. They are regenerated by the
portable launcher and belong under the ignored result directory. The adjacent
`third_party/infllmv2_cuda_impl` checkout was also omitted: it is a pristine
upstream OpenBMB checkout, is not imported by this experiment, and contains no
license file in the recovered revision.

### Experiment-host audits

Three original experiment hosts were audited read-only. Searches covered their
worktrees, tracked histories, reflogs, stashes, ignored files, unreachable
commits/blobs, and adjacent Git repositories. Only one untracked worktree
contained the complete InfLLM-V2 compatibility implementation and archived
outputs. The archived summaries match every value reported in the paper: 59
of 64 evaluated examples trigger sparse routing, exact-Wq improves the
four-dataset average by 0.26, and rank-256 changes it by -0.28 relative to
real-query routing. The archived run also records 140,740 EarlySelect routes
with zero missing routes.

The same host also contained the previously untracked LongAlpaca-12k to
LongBench conversion utility required by the ES-Mix domain-stability launcher.
It was recovered byte-for-byte as
`scripts/probe/prepare_longalpaca_decode_calib.py`. The remaining untracked
MiniCPM and projection-drift probes supported rebuttal exploration but are not
referenced by the final paper; their model outputs and exploratory scripts are
therefore outside the paper-reproduction artifact.

The host did contain recoverable Quest/Loki experiment residue:

- an untracked Mistral LongBench launcher for budgets including 2048/4096;
- a committed launcher that prepares WikiText PCA before Loki evaluation;
- ignored, machine-specific tmux launchers under `zbash/`;
- complete Quest results for Mistral at budgets 128, 2048, and 4096;
- attempted Loki/ES-Loki and ES-Quest runs that stopped on a 24 GB 4090 with
  CUDA out-of-memory before producing predictions.

These launchers are superseded by
`analysis/additional_selectors/run_additional_selectors.sh`, which is
hardware-agnostic, prepares Loki PCA, and covers the complete paper matrix
(including Mistral budget 1024, Qwen2.5-7B, and Qwen2.5-32B). The remote files
were therefore not copied verbatim: they hard-code local proxies, conda
environment names, tmux sessions, and GPU IDs, and do not add missing method
logic. The OOM result is a hardware-capacity observation rather than evidence
that the selector implementation is incorrect.

The A100 host contained two additional uncommitted core robustness fixes. They
were migrated with regression coverage: grouped GQA decode now materializes and
normalizes batched attention biases, and the standard chunked-prefill path uses
the existing chunk iterator so a one-token tail cannot be misclassified as a
decode step. The remaining A100-only files were machine-specific launchers, an
unrelated KVzap prototype, dropped pre-EarlySelect ReMI/UQ experiments, generated
results, and local copies of the paper and reviews; none are required by the
final paper artifact.

### License

The repository now carries a top-level Apache License 2.0. The bundled RULER
utilities retain their Apache-2.0 license in their subdirectory. SCBench was
removed because it is not evaluated or discussed in the final paper.

To keep the release focused on the final paper, the unused LongChat and AIME
configurations, an unconfigured latency-probe hook, and upstream RULER
API/server clients that are not used by the local evaluator were also removed.
The retained RULER data generation, prediction, and evaluation utilities are
the subset exercised by the paper reproduction pipeline.

## Paper/code consistency decisions still required

1. The paper says the default quality setting reserves a recent local tail
   outside routing. The score-producing PyTorch defaults inherited from the
   research repository use `earlyselectkv` / `rocketkv` in pure `hsa` mode.
   A separate `earlyselectkv_hsa_local` implementation exists, but switching
   the default changes the evaluated method and requires rerunning results.

2. `longbench_ruler.pdf` contains `RocketKV_topk` and
   `ES-RocketKV_topk` curves, whereas the prose and numerical tables describe
   one `Exact-TopK` baseline. These are different implementations: standalone
   `topk` attends over the full cache, while the `_topk` variants keep the
   RocketKV Stage-1 cache and replace Stage-2 routing. The reproduction sweep
   now runs both so the final paper can choose one definition consistently.

3. ES-Mix is encoded in the released quality configs as the calibrated layer-20
   transition (`lookahead_mid_until_layer: 20`). The new cross-domain analysis
   recomputes per-layer gaps and assignments, but changing the calibrated
   assignment also requires regenerating the corresponding quality rows.

## Validation performed without full model reruns

- all Python sources compile;
- every JSON config parses;
- every shell entry point passes `bash -n`;
- representative dry-runs resolve all paper methods to concrete pipeline
  modules and exact config paths;
- all 35 model-independent unit tests pass against the pinned public LitGPT
  revision and Transformers 4.57.3; they cover routing utilities, method aliases, long-generation
  capacity, Qwen post-processing, math answer normalization, Exact-TopK,
  Quest last-page behavior, Loki sparse output, low-rank configuration, and
  InfLLM-V2 mask/config behavior;
- CUDA smoke runs on one Qasper example completed model loading, chunked
  prefill, decode, prediction output, and metric evaluation for `baseline`,
  `rocketkv`, `earlyselectkv`, `topk`, `quest`, `earlyselect_quest`, `loki`,
  and `earlyselect_loki`; the Loki runs loaded generated Qwen2.5-7B PCA
  components with identity and real-query fallbacks disabled;
- all nine pipeline CLIs start and expose their command-line interface, and
  the routing-overhead analysis was executed to generate its PNG, PDF, and CSV
  outputs;
- the recovered InfLLM-V2 Python sources compile, its portable launcher
  resolves all eight paper evaluations in dry-run mode, and its archived
  summaries were independently recomputed against the paper table;
- the fixed-trajectory plotter was rerun against the archived 20-example raw
  metrics and successfully regenerated `long_generation_trajectory.pdf`.

These checks establish code/config integrity. Reproducing numerical benchmark
scores still requires the model checkpoints, generated datasets, CUDA GPUs,
and (for Loki) the generated PCA artifacts.
